## What Didn't Work (lezioni operative)

- **Remount-race dei filtri (lezione TD-3 M1, generale)**: il manager della pagina voli è keyed sulla query string → OGNI cambio filtro (e il reset) fa `router.push` e RIMONTA il subtree. Un'interazione e2e lanciata prima che il remount atterri digita in un nodo che sta per essere scartato: su DB voluminoso (render lento) la race si perde deterministicamente. Regola nei test: dopo OGNI azione che naviga, settle su un osservabile del nuovo albero (URL + scomparsa del valore sporco — `resetFiltersAndSettle` in `flight-log.spec.ts` è il pattern) prima della prossima interazione.
- **Assert run-unique, sempre (ri-lezione 6.3 F1)**: "periodo+tipo → 1 riga" fallisce appena il TEST STESSO è girato più volte sullo stesso DB (ogni esecuzione lascia un volo June/OTHER). Ogni assert di conteggio deve essere ancorata a un'entità run-unique (persona/velivolo col suffisso random).
- **Workflow morto senza StructuredOutput** (TD-3 dev, dopo 62'): il lavoro sul filesystem era completo — controllare SEMPRE `git status` + transcript prima di ri-lanciare da zero. `resumeFromRunId` NON aiuta se la chiamata agent() è FALLITA (ri-eseguirebbe tutto).
- Il subagent dev che aspetta un run e2e in background con poll `true` brucia il contesto residuo: nei prompt dev futuri, chiedere di lanciare i run lunghi PRIMA delle scritture di chiusura, o di chiudere il report anche con un gate "in corso, ripreso dalla sessione principale".

## Key Decisions (oltre a PRD/spine/CLAUDE.md e story files)

- **Idempotenza richieste (TD-2)**: chiave per-UTENTE (`@@unique([userId, endpoint, key])` — stesso key da utenti diversi non collide né replay-a cross-user); gate nel layer API (`apiRoute`), MAI nei service (AD-5 intatto); gate DOPO la validazione Zod (una richiesta malformata non tocca la tabella); errore (4xx/5xx) LIBERA il key (i service sono transazionali: errore = nessuna scrittura); PENDING orfani mai auto-scaduti (auto-expiry = rischio doppia esecuzione, peggio del blocco; il client manda un key nuovo dopo verifica manuale); nessun job di cleanup (crescita lenta, documentato). Il replay è deep-equal ma NON byte-identico (JSONB riordina le chiavi) — rilevante solo se un client facesse hash dei byte.
- **SearchCombobox (TD-3)**: UN componente riusabile; `initialOptions` server-rendered come risposta immediata (≤100 funziona senza fetch), ricerca server-side `q` oltre; il componente POSSIEDE il pairing label-sibling-htmlFor (lezione 5.4 by-construction); `openWithOptions` invalida seq+debounce pendenti (D3). Form picker seeded dalle query `profile`-filtrate: pagina 1 vuota ⟺ insieme vuoto → gating `disabled` esatto (D2).
- **`profile` su `GET /people`**: additivo, opzionale (`pilot-or-student`/`instructor`), filtra i profili ATTIVI, combinabile con `q` — è il contratto dei picker del form voli; la barra filtri resta senza profile e con `includeArchived: true`.
- Finding CHIUSI per decisione (non-difetti, confermati dall'utente): 4.3 F2 (un messaggio generico per 409 nelle form — convenzione), 2.5 F4 (rettifica contaore su velivolo fuori servizio/archiviato = legittima), 2.5 F5 (409 generico su return-to-service).
