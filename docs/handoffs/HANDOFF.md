(b) **una run e2e locale in dev-mode può essere verde dove il CI-mode fallisce** (12.3: 22 pass locali vs 16 fail CI; 12.5: il dev non ha mai visto il CI-mode, che ha trovato il fixture rotto) — il gate è SOLO `CI=1` su build prod; (c) **il dev può OMETTERE silenziosamente un deliverable richiesto** (12.6: il test e2e del profilo dell'AC-7 mai scritto — feature funzionante, gates verdi, report del dev che elencava gli ALTRI spec e taceva questo → NIENTE lo segnalava tranne l'audit). Il safeguard è la **REVIEW che fa il diff dell'inventario test contro gli AC** (NON il ri-run del dev: un dev fresco potrebbe ri-omettere lo stesso test). Prassi da mantenere: reviewer verifica ogni AC → codice + test, con evidenza empirica; (d) subagent commit già con l'identità giusta — niente amend necessario; (e) **la review interrotta va ri-eseguita**: se una sessione precedente ha applicato fix di review ma non ha persistito i findings, ri-lanciare l'adversarial-reviewer sul tree corrente (fatto per 12.4 — 210/210, nessun findings perso).
