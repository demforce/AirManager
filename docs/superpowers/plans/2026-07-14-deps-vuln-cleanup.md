# Dependency Vulnerability Cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Clear the fixable `npm audit` vulnerabilities (10 → 2) and the uuid deprecation warning by bumping nodemailer to 9.0.3 and adding three npm overrides — `package.json` + lockfile only, no source changes.

**Architecture:** Single-commit dependency maintenance per the approved spec (`docs/superpowers/specs/2026-07-14-deps-vuln-cleanup-design.md`). The nodemailer major bump is safe because the only consumer is `src/server/adapters/mail/smtp-mail-sender.ts`, which uses just `createTransport({host, port, secure})` + `sendMail({from, to, subject, text, html})` — a surface unchanged in v9. The `"$nodemailer"` override aligns next-auth/@auth/core's optional peer (`^7.0.7`) to avoid ERESOLVE. Remaining audit findings (next→postcss chain) and 5 exceljs deprecation warnings are accepted per spec.

**Tech Stack:** npm overrides, nodemailer 9.0.3, existing gates (`npm run gates`) and Playwright e2e as the safety net.

**Branch:** `chore/deps-vuln-cleanup` (already created; spec committed as `3731f30`).

### Task 1: Update package.json and verify the dependency tree

**Files:**
- Modify: `package.json` (dependency version + new `overrides` block)
- Modify: `package-lock.json` (regenerated by npm — never edit by hand)

- [ ] **Step 1: Edit `package.json`**

In `dependencies`, change:

```json
    "nodemailer": "7.0.13",
```

to:

```json
    "nodemailer": "9.0.3",
```

After the `devDependencies` block (as a new top-level key, before the closing `}`), add:

```json
  "overrides": {
    "nodemailer": "$nodemailer",
    "exceljs": {
      "uuid": "^11.1.1"
    },
    "@hono/node-server": "^1.19.13"
  }
```

Note: the `"$nodemailer"` reference syntax is required — a literal version here would trip npm's EOVERRIDE check ("Override for nodemailer conflicts with direct dependency") and it keeps the override in lockstep with the dependency version.
